# Japan Phrase Trainer

Small static web app (single `index.html`, no build step, no dependencies except Google Fonts) for practising Japanese travel phrases before a trip to Japan (arrival 2027-01-01). Owner: Daniel, German teacher/Informatik, learning with Genki I (3rd ed.). Chat and explanations with him: English. Phrases and UI: English/Japanese.

## Current state
- Phrase cards (Week 1 set, `PHRASES` array): kana, romaji, English, accepted kanji spellings (`alt`), tolerated particle spelling (`soft`, e.g. わ for は).
- Romaji -> kana converter (`convert`): capital first letter = katakana word, `ha` types は, `-` = ー.
- Answer check (`checkAnswer`): normalises hiragana/katakana, accepts kanji variants, per-character diff against the model phrase.
- Audio: pre-rendered files in `audio/` (`<id>.m4a`, `<id>.slow.m4a`, id from `audioId()` = slugged romaji), generated by `node make-audio.js`. The page plays the file and falls back to `speechSynthesis` only when there is none.
  - `s` on a phrase is the spelling given to the speech engine (kanji where the reading is unambiguous, so は is read as a particle and words segment properly); spaces in `s` are the pause points of the slow take.
  - Slow = a pause between chunks at near-normal rate, not a stretched utterance, which smears Apple's compact voices.
  - Voice selection in the fallback must never take the first `ja-JP` match: Apple's novelty voices (Eddy, Flo, Grandma, Grandpa, Reed, Rocko, Sandy, Shelley) are all tagged ja-JP and sort ahead of Kyoko.
  - `make-audio.js` probes a ranked list of voice identifiers and picks the best one that actually renders; `--voice <id>` overrides. `say -v <id>` accepts an identifier for a voice that is only registered, and renders silence rather than failing, so every candidate and every take is checked by duration. As of 2026-11-03 the files are rendered with `com.apple.voice.enhanced.ja-JP.Kyoko`. Premium Kyoko stays a stub even with everything downloaded — Japanese appears to have no Premium tier, so Enhanced is the ceiling for Apple voices here. On macOS 27 the voices live under System Settings → Accessibility → **Read & Speak** ("Spoken Content" was renamed; the internal id is still SpokenContent).
- Two card toggles: "Hide kana, recall from English" (session only) and "Show romaji" (off by default, remembered in localStorage). Romaji is also suppressed while kana is hidden, so it cannot give the answer away.
- Done-state in localStorage.
- Pure logic is at the top of the script and testable in Node: `node test.js`.

## Why this moved out of the Claude artifact
The artifact sandbox blocks the microphone. As a normal https site (GitHub Pages) the page can use the Web Speech API (`webkitSpeechRecognition`, lang `ja-JP`) directly. That is the main next step.

## Roadmap
1. Add speech recognition (mic button): show transcript, compare via `checkAnswer` (recognizer returns kanji -> keep `alt` lists, use `maxAlternatives`). Handle iOS Safari quirks and permission denial gracefully.
2. More phrase sets by week (numbers/prices, food, transit, hotel, sights, New Year closures: やっていますか). Move `PHRASES` into a JSON file per week.
3. Signage kanji flash deck (出口, 入口, 駅, 男, 女, 禁煙, 乗り換え ...), recognition only.
4. Optional: scenario/role-play mode (needs an LLM backend; decide later whether to add one).
5. Deploy on GitHub Pages; keep it a static site.

## Conventions
- Keep it dependency-free and mobile-first (iPad/iPhone Safari). Inputs >= 16px, touch targets >= 44px.
- Light/dark via CSS tokens in `:root`, no hard-coded colours elsewhere.
- Verify any change to converter/check logic with `node test.js` before committing.
- After adding or editing phrases, re-run `node make-audio.js`. It reads `PHRASES` straight out of `index.html` (same `vm` trick as `test.js`), so the phrase list stays the single source of truth.
- `.claude/launch.json` serves the folder on :8777 for previewing; the audio only resolves over http, not from a `file://` page.
